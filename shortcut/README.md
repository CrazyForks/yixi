# 一息 · iOS 快捷指令配置手册

把「打开小红书」这个动作接到一息的闸门上，全部在 iPhone 自带的「快捷指令」App 里完成，不需要越狱、不需要装任何第三方 App。

配置一次约 5 分钟，之后每多拦一个 App 再花 1 分钟。

---

## 开始之前

你需要两样东西：

| 东西 | 长什么样 | 从哪来 |
|---|---|---|
| **服务地址** | `https://yixi.<你的子域>.workers.dev` | 部署完 Worker 后 Cloudflare 给你的地址，见项目根目录 `README.md` |
| **你的 token** | 32 位十六进制，形如 `9f3c...` | owner 在 `/admin` 页面给你生成，**只显示一次**，当场存进密码管理器 |

下文统一把服务地址写成 `<你的地址>`，把 token 写成 `<你的token>`，照抄时记得替换。

还需要先在网页里把要拦的 App 配好：浏览器打开 `<你的地址>/settings?k=<你的token>`，加一条记录。其中 **app 键**（比如 `xhs`）是后面自动化里要手打的那个字符串，两边必须一模一样，大小写敏感。

> 界面文案以 iOS 中文版为准。不同 iOS 版本措辞会有出入（比如「获取 URL 的内容」在有的版本叫「获取 URL 内容」）。找不到动作时，用英文名搜更稳：Text / Get Contents of URL / Get Dictionary Value / If / Open URLs / Run Shortcut。

## 第一步：建一个快捷指令「一息」

**整套配置里，只有这个快捷指令里有你的 token，而且只有一处。** 后面每个 App 的自动化都只是调用它，不重复填 token。将来 token 轮换，只改这一个地方。

打开「快捷指令」App → 右上角「+」新建 → 重命名为 **一息**。

然后依次加这几个动作：

### 动作 1 ——「文本」

内容填你的 token，**只有这一行需要改**：

```
<你的token>
```

### 动作 2 ——「获取 URL 的内容」

- **URL** 字段填（`[快捷指令输入]` 和 `[文本]` 是变量，不是字面文字，插法见下）：

  ```
  <你的地址>/gate?app=[快捷指令输入]&k=[文本]
  ```

- 展开「显示更多」，**方法**选 `GET`，请求头和请求体都留空。

插变量的方法：光标放在 URL 字段里要插入的位置，点键盘上方那条变量栏，选「快捷指令输入」或上一步的「文本」。如果变量栏没出现，长按字段 →「选择变量」。

> **这里最容易出错**：`app=` 后面必须是变量「快捷指令输入」，不是手打的 `xhs`。app 键由每条自动化各自传进来 —— 这正是一个快捷指令能服务所有 App 的原因。

### 动作 3 ——「获取词典值」

- **获取**：`值`
- **键**：`action`
- **来源/输入**：「URL 的内容」（动作 2 的输出，通常会自动填好）

### 动作 4 ——「如果」

- 条件：**「词典值」** 「等于」 `block`

> 必须是「**等于** block」，不能写成「**不等于** pass」。这一条决定了服务挂掉时你还能不能打开自己的 App，理由见下面「坏掉的时候必须放你进去」。

下面两个动作放在「如果」和「结束如果」**之间**：

### 动作 5 ——「获取词典值」（在如果内部）

- **键**：`url`
- **输入**：手动改成 **「URL 的内容」**

> **第二个大坑，务必检查**：这一步的输入默认会指向「如果」的输入，而不是动作 2 的结果。不改的话取不到 url，点开 App 时什么都不会发生，而且不报错。点一下输入框把变量换成「URL 的内容」。

### 动作 6 ——「打开 URL」（在如果内部）

- URL：上一步的「词典值」

### 完整形状

```
文本                      <你的token>
获取 URL 的内容            <你的地址>/gate?app=[快捷指令输入]&k=[文本]   方法 GET
获取词典值   键 action     输入 = URL 的内容
如果  词典值  等于  block
    获取词典值   键 url     输入 = URL 的内容     ← 输入要手动改
    打开 URL     词典值
结束如果
```

服务端返回 `{"action":"pass"}` 时「如果」不成立，快捷指令直接结束，你无感进 App；返回 `{"action":"block","url":"..."}` 时才跳呼吸页。

### 最要紧的一条：坏掉的时候必须放你进去

上面动作 4 的条件写的是「**等于** `block`」。这不是随手写的，**永远不要改成「不等于 `pass`」**。

差别在服务出问题的时候。`/gate` 有一堆理由给不出正常答复：token 被换掉了（401）、Worker 挂了、网络超时、Cloudflare 抽风、返回了空。

- 写成「**等于 block 才打开 URL**」：上面每一种异常都不等于 `block`，「如果」不成立，快捷指令什么都不做直接结束，**你的 App 正常打开**。最坏的结果是「今天没拦住你」。
- 写成「**不等于 pass 就打开 URL**」：服务一挂，每次开 App 都会跳去一个打不开的网页。你被自己写的工具**锁在自己的手机外面**，而且当时多半正急着用。

这两种坏法完全不对等：一边是少拦一次，一边是几个 App 全废。所以这个工具的默认行为必须是 **fail-open** —— 拿不准就放行。

同样的道理还有两条：

- **不要给「获取 URL 的内容」加任何出错处理。** 网络失败时 iOS 会让整条快捷指令直接中止，中止意味着后面的「打开 URL」根本不会执行，App 照常打开——这正是我们要的。加「出错时重试」只会让你在没信号的时候多等几秒；加「出错时打开某个网址」会把 fail-open 变成 fail-closed。
- **不要在「如果」后面加「否则」分支去打开任何东西。** 「否则」就是「服务没说要拦」，那就该什么都不做。

### 先单独测一次

**别在快捷指令编辑页里直接点运行**——那样没有输入，`app=` 会是空的，服务端返回 400，快捷指令会报一个和你的配置无关的错，白白吓自己一跳。

要验 URL 和 token 对不对，直接在 Safari 地址栏打开这个：

```
<你的地址>/gate?app=zzztest&k=<你的token>
```

`zzztest` 是一个故意没配置过的 app 键。服务端对没在管的 App 一律放行，而且**什么都不记**，所以这个测试没有任何副作用。对照返回：

| 看到什么 | 说明 |
|---|---|
| `{"action":"pass"}` | URL 和 token 都对，可以往下走了 |
| `{"error":"unauthorized"}` | token 不对。多半是复制时带了空格 |
| `{"error":"missing app"}` | 网址里 `app=` 后面是空的 |
| 连不上 / 404 | 服务地址写错了，或者 Worker 没部署成功 |

想连自动化一起验，就直接去做第二步，然后从桌面点开那个 App——那才是真实路径。注意用真实 app 键去打 `/gate` 会**真的记一次拦截**并开一个 session，所以别拿它当反复重试的测试工具。

## 第二步：为每个 App 建一条自动化

「快捷指令」App → 底部**「自动化」**标签 → 右上角「+」。

1. 在触发条件列表里选 **「App」**
2. 「App」一行点进去，勾选**要拦的那个 App**（一次只选一个，理由见下节）
3. 选 **「已打开」**（不是「已关闭」），点「下一步」
4. 进入动作编辑页，加两个动作：

   **动作 1 ——「文本」**：填这个 App 在 `/settings` 里的 **app 键**，例如：

   ```
   xhs
   ```

   **动作 2 ——「运行快捷指令」**：
   - 快捷指令：选 **一息**
   - 展开「显示更多」，**输入**：设为上一步的「文本」

5. **关掉「运行前询问」**（有的版本叫「运行前询问」，有的在下一页叫「立即运行 / 运行前询问」二选一）。关掉时系统会再弹一次确认，选「不询问」。
6. 顺手把「运行时通知我」也关掉，否则每次开 App 顶上都会弹一条横幅。
7. 完成。

### 每个 App 都要重来一遍，这是 iOS 的限制

**「打开 App 时」的自动化必须一个 App 建一条，无法批量、无法一条自动化选多个 App。** 拦 5 个 App 就得手动建 5 条自动化。

这不是一息偷懒 —— One Sec 和所有同类工具都是这么装的，iOS 没有给出别的口子。

好消息是重复的部分很少：每条自动化只有两个动作，其中唯一要改的是那行 app 键的文本。token 和 URL 都在第一步那个共用快捷指令里，不用重复填。

## 第三步：跑通一次

1. 从桌面点开你刚配置的 App
2. 应该会闪一下跳到 Safari，出现呼吸页
3. 等倒计时结束
4. 点「算了」→ 页面给你一句话，你自己退出去
5. 或者点「继续」→ 应该跳回目标 App

第 5 步跳不回去，说明 URL scheme 不对，去看下面的排障。

跳回 App 的一瞬间，「打开 App 时」自动化**会被再次触发**，这是正常的。服务端有 90 秒的 grace 窗口，这次会直接放行，你不会被连环拦截，统计里也不会把它算成一次冲动。放下手机超过 90 秒再拿起来，才会重新拦你 —— 这是刻意设计的。

---

## 回来后必须亲自验证的三件事

这三件事机器替不了，而且任何一件不成立，方案都要改：

- [ ] **「运行前询问」能不能真的关掉**，关掉后开 App 是不是零点击直接跑。如果每次都要手动确认，这工具就从「提醒」变成了「骚扰」，不可用。
- [ ] **「获取 URL 的内容」的延迟能不能忍**。每次开 App 都要等一次网络往返；如果卡到有明显顿挫感，得退回备选方案（快捷指令直接开网页、grace 改前端判断，代价是多一次点击）。
- [ ] **点「继续」能不能跳回目标 App**。这条断了整个链路就断了，只能对那个 App 放弃拦截。

验证完把结果填回本文档末尾的表。

## URL scheme：候选清单，全部未验证

**下面这些 scheme 全部标注为「未验证」，一个都不要直接抄进配置。**

App 的 URL scheme 随版本变化，网上流传的清单大量过期，凭记忆写死是这个项目最容易踩的坑：scheme 写错的表现不是报错，而是你点了「继续」之后卡在 Safari 里哪也去不了。

正确做法：浏览器打开 **`<你的地址>/probe`**，页面会把你配置的每个 App 列成一个大按钮，在 iPhone 上挨个点 —— **跳得动的才算数**。也可以在那个页面顶部的输入框里直接试候选 scheme，不用先存进配置。

|---|---|---|
| 小红书 | `xhsdiscover://` | 未验证 |
| 抖音 | `snssdk1128://` | 未验证 |

## 排障

### App 打不开了 / 每次开 App 都跳到一个打不开的网页

**先止血：去「快捷指令」→「自动化」，把那条自动化的开关关掉**（或者直接删掉）。App 立刻恢复正常。一息挂了不该影响你用手机。

止完血再查原因，通常是两种：

1. **服务真的挂了**。在 Safari 里打开 `<你的地址>/gate?app=zzztest&k=<你的token>`，看得到 `{"action":"pass"}` 就说明服务是好的。
2. **你把「如果」的条件改错了**，写成了「不等于 pass 就打开」。回上面那节「坏掉的时候必须放你进去」，把条件改回「等于 `block`」。

条件写对的话，服务挂掉的表现应该是「不拦你了」，而不是「打不开 App」。如果表现是后者，那就是快捷指令写错了，不是服务的问题。

### 点「继续」跳不回 App

大概率是 scheme 不对。

1. 打开 `<你的地址>/probe`，找到这个 App 的按钮，点一下
2. 跳走了 → scheme 是对的，问题在别处（往下看「呼吸页点了没反应」）
3. 没反应、或弹「Safari 打不开该页面」 → scheme 不对
4. 在 `/probe` 顶部的输入框里换个候选试，试到跳得动为止
5. 试通了，去 `/settings` 把这个 App 的 scheme 改成对的那个

一个 scheme 都试不通，说明这个 App 不支持从 Safari 唤起，见上一节末尾。

### 呼吸页点了「继续」，页面没动也没跳

Safari 只允许在**你手指点击的那一瞬间**跳自定义 scheme。如果点击和跳转之间隔了网络请求，Safari 会把它当成非用户操作拦掉。呼吸页是按这个约束写的，所以正常不会遇到；真遇到了，先确认是不是在「无痕浏览」或某个内嵌浏览器里打开的，用正常的 Safari 再试一次。

### 打开 App，自动化压根没触发

按可能性从高到低排查：

1. **「运行前询问」没关干净** —— 回自动化详情页再确认一次，有的版本关掉后还要再点一次确认弹窗
2. **选错了触发条件** —— 必须是「已打开」，不是「已关闭」
3. **不算「打开」** —— 从后台切回前台在部分 iOS 版本上不触发。先把 App 从后台划掉，再从桌面点开
4. **自动化本身被关了** —— 自动化列表里每条右侧有开关，检查是不是灰的
5. **系统抽风** —— 重启 iPhone。「打开 App 时」自动化偶发失灵是 iOS 的老毛病，重启通常能恢复

### 每次都直接进 App，从来没被拦过

自动化跑了，但服务端判定「不管这个 App」：

- **app 键对不上**：自动化里那行文本必须和 `/settings` 里的 app 键一字不差（大小写敏感）。`XHS` ≠ `xhs`
- **enabled 被关了**：去 `/settings` 看这条记录的启用开关
- **一直在 grace 窗口里**：刚从这个 App 出来不到 90 秒又点回去，会直接放行。这是设计行为，等 90 秒再试

### 刚点了「继续」跳回 App，马上又被拦

grace 窗口没生效。要么 `/resolve` 没打成功（网络断了），要么 `grace_seconds` 设得太短。去 `/settings` 把这个 App 的 grace 秒数调大一点（默认 90 秒）。

### 快捷指令报 401 / 提示无法获取内容

token 不对。常见原因是复制时带了首尾空格，或者 token 已经被 owner 重新发过。回第一步动作 1 检查那行文本，注意末尾不能有换行或空格。

### 呼吸页放了很久，还能点「继续」吗

能。已经打开的那一页上的「继续」永远有效，服务端不看你等了多久——因为拒绝它就开不出免打扰窗口，跳回 App 时会被自动化立刻再拦一次，转进死循环。

但如果你把那一页**刷新**了，或者从历史记录里重新打开它，超过 10 分钟的链接会显示已失效。这时候退出去重新点一次 App 就行。

### 开 App 明显变慢

每次开 App 都要等一次到 Cloudflare 的网络往返。信号差的时候会有感知。目前没有客户端缓存 —— 如果慢到不可接受，见上面「回来后必须亲自验证的三件事」第二条，这属于要改方案的信号，不是配置问题。
