# 一息 · iOS 快捷指令

> **配置步骤请看应用内的 `/setup` 页面，不要照抄这里。**
>
> 那一页知道你的地址、你的 token、你配了哪些 App，印出来的是可以直接长按复制的成品；
> 这份文档只能写占位符让你自己替换，而替换错正是这套配置最常见的失败方式。
>
> 本文档留下的是**为什么这么设计**——那部分不随人变化，也不该塞进手机上的操作指引里。

## 整体形状

```
打开小红书 → iOS「打开 App 时」自动化
   → 快捷指令：获取 URL 的内容  ← 网址由自动化传进来
        GET  https://<你的地址>/gate?app=xhs&k=<token>&fmt=text
   → 如果「URL 的内容」包含 https
        → 打开 URL「URL 的内容」   ← 呼吸页
   （不包含就什么都不做，App 正常打开）
```

快捷指令**三个动作，一次都不用挑变量**。它本身不含 token、不含 App 名，所以一辈子只建一次，
还能直接拷 iCloud 链接送人。每个 App 的差异全在自动化里那一行粘贴的网址。

## 为什么服务端要回纯文本

最早 `/gate` 回的是 JSON，快捷指令要「获取词典值」取 `action`、用「如果」比较词典值、
再「获取词典值」取 `url`——六个动作、三次插变量。实测发现**「如果」的编辑器并不可靠地把
词典值作为可比较对象给出来**，用户直接卡死在这一步。

所以改成 `fmt=text`：服务端直接回一条 `https://…` 网址或者 `pass` 这个词。
解析的活服务端干了，快捷指令只剩一次字符串包含判断。

## 「包含 https」不是随手写的

这一条同时承担两件事：该拦时打开呼吸页；以及——**任何异常都自动放行**。

`/gate` 有很多种给不出正常答复的理由：token 被换了、Worker 挂了、网络超时、
返回一片空白、DNS 被污染。这些回答里**没有一个含有 `https`**，所以「如果」不成立，
快捷指令什么都不做，你的 App 正常打开。最坏的结果是「今天没拦住你」。

反过来写成「**不包含 `pass` 就打开**」的话，服务一挂，每次开 App 都会跳去一个打不开的网页，
你会被自己写的工具**锁在自己的手机外面**，而且当时多半正急着用。

这两种坏法完全不对等：一边少拦一次，一边几个 App 全废。所以默认行为必须是**拿不准就放行**。

同理还有两条：

- **不要给「获取 URL 的内容」加出错处理。** 网络失败时 iOS 会让整条快捷指令中止，
  中止意味着后面的「打开 URL」根本不会执行，App 照常打开——这正是要的。
- **不要在「如果」后面加「否则」去打开任何东西。** 「否则」就是「服务没说要拦」，那就该什么都不做。

## 一个 App 一条自动化，这是 iOS 的硬限制

「打开 App 时」的自动化**必须一个 App 建一条**，不能批量、不能一条里选多个。
拦 5 个 App 就是 5 条。One Sec 和所有同类工具都这样，代码层面消不掉。

## URL scheme 不要凭记忆写

App 的 URL scheme 随版本变化，网上流传的清单大量过期。写错的表现不是报错，
而是你点了「继续」之后卡在 Safari 里哪也去不了。

**用应用内的 `/probe` 页逐个实测**——把配置里每个 App 列成一个大按钮，
在 iPhone 上挨个点，跳得动的才算数。那一页故意用和呼吸页完全相同的跳转方式
（点击处理函数里同步 `location.href`），所以在那儿能跳，在呼吸页就一定能跳。

有些 App 已经彻底移除了自己的 scheme，怎么点都不动。这种没有代码层面的解法：
要么对它放弃拦截，要么接受「点完继续自己再手动点一次图标」（第二次会落在免打扰窗口里，不会再被拦）。

## 排障

应用内 `/setup` 页面底部有完整的排障清单，包括：App 打不开了怎么止血、
点「继续」跳不回去、自动化压根没触发、每次都直接进 App 没被拦、
刚点继续跳回去又被拦、开 App 明显变慢。

有一类错误值得单独提一句：**`kCFErrorDomainCFNetwork`**。
这是 iOS 网络层的错，意思是那条请求根本没发出去——通常是网址复制时缺了一截，
或者混进了省略号之类的非法字符。**先在 Safari 里直接打开那条网址**
（`/setup` 的粘贴区每行下面都有「在 Safari 里试一下这条」），
看到 `pass` 就说明地址没问题，再去查快捷指令。
